## 🎓 Para Demostrar en Entrevista

### Pregunta: "Tell me about your testing strategy"
**Respuesta**:
"I follow ISTQB principles with shift-left testing. I chose Cypress over Selenium because of reliability and modern JavaScript support. I use IndexedDB for test data instead of backend API to ensure test isolation. I test on 4 browsers using BrowserStack for cross-platform validation. I use risk-based approach: 35% on critical features, 40% on high-priority, 20% medium, 5% low. Results: 98.5% pass rate."

**Referencia**: QA_STRATEGY.md Sections 2-6

### Pregunta: "How do you manage defects?"
**Respuesta**:
"I use a standard bug report template with severity/priority levels. Critical bugs get 2-hour response time. I track in Google Sheets with automated workflow: New → Assigned → Investigation → Fixed → Verification → Closed. Each bug is linked to test case that caught it."

**Referencia**: BUG_REPORT_TEMPLATE.md Section 7

### Pregunta: "Why Cypress?"
**Respuesta**:
"Cypress is more reliable than Selenium - no flaky tests. It has better debugging with time-travel. Fast execution (3-4 minutes for 100+ tests). Perfect for modern React apps. Active community. These factors led to our <2% flakiness rate."

**Referencia**: QA_STRATEGY.md Section 4.1
